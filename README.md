# Amazons Desktop

独立本地桌面亚马逊棋平台，Python 3.12 + Tk，Pillow 用于抗锯齿棋盘绘制。打包版自带全部依赖。

## 启动和构建

在仓库根目录使用 Make（Windows 当前环境已安装），可通过 `PYTHON=完整路径` 指定 Python：

- `make install`：安装运行依赖。
- `make install-build`：安装构建依赖。
- `make run`：从源码启动。
- `make check`：编译检查源码。
- `make build`：生成并覆盖 `dist/AmazonsDesktop.exe`；构建前关闭程序。
- `make clean`：清理构建缓存，保留可执行文件。
- `make distclean`：同时清理可执行文件；执行前关闭程序。

直接启动源码也可使用 `python desktop/launcher.py`。打包后双击 `dist/AmazonsDesktop.exe` 即可运行。未安装 Make 时，可直接执行 Makefile 对应目标中的命令。

## 目录结构

```text
src/amazons_desktop/
  __main__.py         桌面启动与 DPI 设置
  game.py             规则和完整回合
  clock.py            对局计时
  engine.py           SAU 引擎进程适配
  record.py           JSON / TXT 棋谱与回放局面
  ui/
    app.py            窗口布局与交互协调
    board_view.py     棋盘和棋子绘制
    record_dialog.py  对局信息与导出对话框
    theme.py          共享配色、输入控件与弹窗主题
desktop/
  launcher.py         源码及打包入口
  application.manifest Windows DPI 清单
tools/clean.py        构建清理工具
tests/               规则、桌面交互和引擎验证代码
Makefile             统一开发、构建和清理入口
requirements*.txt    运行及构建依赖
dist/                唯一的最新版程序（不入库）
build/               中间构建文件（不入库）
```

包内使用相对导入；源码根为 `src`，独立运行测试脚本时需将 `src` 加入 `PYTHONPATH`。

## 操作

黑方先行，10×10 棋盘，上方为白棋，布局与现有 Amazons 引擎一致。点击己方棋子、圆点移动位置、空心蓝圈射箭位置完成回合。Esc 撤销尚未完成的选择或移动。箭可以射回腾空的原位。

两侧分别选择“人类”或“加载引擎”，支持双人、人机、双引擎。新建棋局、改变玩家或调整时限后进入准备状态：可先设置双方玩家和对局信息，引擎在后台加载并确认名称，棋盘禁止落子，时钟保持停止。双方引擎就绪后“开始对局”按钮可用；点击后才发送开局命令、启动计时并允许行棋。对局开始后该按钮禁用，重复点击不会重开。引擎选择框默认打开 `D:/Myfile/code_repos/Amazons/output/submission`，进入对应时间戳目录选择 `policy-submission.exe`。模型、ORT、CUDA 等环境仍由引擎自身编译配置决定，平台不会复制或改变模型配置。

“保存 JSON”保存原生棋谱，UTF-8 无 BOM，保留对局信息和完整走法；格式为 `{"format":"amazons-sau-1","metadata":{"black":"黑方","white":"白方","result":"先(后)手胜","location":"时间地点","event":"赛事"},"moves":["AGAFAG"]}`。无 metadata 的早期 JSON 仍可读取。

“导出比赛 TXT…”按比赛规范生成纯文本棋谱，**严格 GB2312 编码，无 BOM**。导出前填写/确认先后手参赛队、比赛结果（先手胜/后手胜）、比赛时间及地点、赛事名称。“对局信息…”可提前编辑这些信息。无法用 GB2312 表示的字符会提示修改，禁止替换或丢弃。文件名由用户选择。

棋盘显示使用相同的 a–j、下方为 1 的坐标，对局记录也显示棋谱着法。

TXT 第一行为 `#[AM][先手参赛队][后手参赛队][后手胜][2017.07.29 14:00 重庆][2017 CCGC];`。之后每行记录一回合：`1 d1i6(f9) g10g4(b4)`，使用英文标点。坐标原点左下，列 a–j、行 1–10；这与 SAU 协议从上往下的 A–J 坐标分别转换。最后一回合可只有黑方走法。读取 TXT 兼容 GB2312 及此前 C++ Recorder 输出的 GBK 文本；新导出严格使用 GB2312。

JSON 与 TXT 都可直接打开回放。回放时钟停止，支持首手、上一步、播放/暂停、下一步、末手和进度条跳转。自动播放每秒推进一手。“从此处继续”保留当前位置之前的走法，转为本地双人准备状态；点击“开始对局”后重新计时；回放模式保存/导出会保留整份原棋谱。

双人悔棋撤销一手；支持扩展的引擎对局撤销两手，回到人类行动。所有引擎空闲时才可悔棋，搜索中按钮禁用。悔棋同步恢复棋盘、箭、行动方和计时；恢复时清除旧结果。每方总时限可选择 100、300、750、900 秒或不限时；修改时限会新建棋局。默认每方 900 秒，与引擎的 100 秒累计搜索预算独立。显示剩余时间、本手用时及全局累计用时；不限时显示累计已用时间。准备和引擎初始化不计时，点击“开始对局”后开始计时；超时立即判负并停止引擎；引擎超时后需新建棋局。双人支持暂停，暂停期间禁止走棋；引擎模式不暂停。悔棋同时恢复上一回合结束时的计时。棋谱不携带用时；回放不计时，从此处继续时重置双方时钟并等待点击开始。对局记录显示走法与引擎诊断；错误后可通过新建棋局重启。引擎响应超时为 180 秒。

## SAU 协议

现行命令：`name?`、`new black|white`、`move X1Y1X2Y2X3Y3`、`end black|white`。每条以换行结束。坐标 A–J，先列后行，自左向右、自上向下。黑方收到 `new black` 立即计算第一步，白方等待对手走法；收到 `move` 后更新对手走法并返回自己的走法。旧协议 stdout 输出 `name ...` / `move ...`，stderr 为诊断。平台独立校验每条完整走法。

### 悔棋扩展

- `name AmazonsPolicy [undo,go]`：在现有名称响应中声明扩展能力。未声明的引擎照常对弈，悔棋按钮禁用，不探测未知命令。
- `undo N`：撤销最近 N 个完整回合，恢复棋盘、行动方、历史及棋谱，销毁整个搜索会话和旧树，建立全新会话；不自动搜索。回复 `ready`。
- `go`：在本方行动时明确开始搜索，仍返回 `move X1Y1X2Y2X3Y3`。
- 调用方保证 N 为正数且不超过历史长度，所有引擎均已空闲且支持扩展；不使用静默兼容降级。
- UI 记录每个引擎已观察的手数，分别发出恢复到同一局面的 `undo N`；终局最后一手可能未传给另一引擎。等待全部 `ready` 后恢复本地规则和计时，若恢复后的行动方是引擎则发送 `go`。
- 引擎对局撤销两手，保证所有参与引擎都回退并销毁旧搜索树；人机模式回到人类行动方，双引擎模式在终局后可撤销并继续。双人单次撤销一手。
- 搜索中悔棋暂不属于扩展范围；后续若支持应另行约定停止搜索与旧响应清理的语义。

## 检查与范围

语法检查：`make check`。生产构建包含 Windows PerMonitorV2 DPI 清单。程序固定输出到 `dist/AmazonsDesktop.exe`，重复构建覆盖该文件，不创建版本子目录；构建前关闭正在运行的程序。

当前未自动持久化玩家配置；没有联网对弈或引擎参数编辑。引擎无需启动参数，适配当前已编译 submission。跨显示器 DPI 切换仍需在多显示器环境体验确认。
